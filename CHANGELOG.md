# Changelog

All notable changes to commit-rules.json, validator, and reusable workflows.

Versioning: SHA-pinned by consumers. Existing rule_ids are immutable once shipped; breaking changes land as NEW rule_ids.

## [Unreleased]

### Added
- **HA app docs standard (new)**: `specs/ha-app-docs-contract.md` + `specs/ha-app-docs-rules.json` — drift-proof install-docs contract for Home Assistant app/add-on repos. Requires a My Home Assistant redirect badge for install and bans stale nav wording (`ADDON_STORE`, `SETTINGS_ADDONS`, `HASS_IO`). Markdown-aware linter (`actions/ha-app-docs-lint/`, reusable GitHub Action) skips badge URLs, code fences, and `CHANGELOG*` — measured naive-substring ~45% false-positive → markdown-aware ~0% across 11 real repos. Ships a 14-case corpus (`specs/ha-app-docs-test-corpus/`), a conformance test, and the `ha-app-docs-test.yml` self-test workflow. Repo-type profiles (`addon` / `hacs-integration` / `hacs-frontend`). The install-badge rule requires a known-good redirect slug and ignores code-fenced / commented-out / dead-slug badges; profile checks are repo-level (README + `docs/`); the linter fails closed on missing paths and zero-doc scans; the reusable action passes inputs via env + argv array (no shell interpolation); fence-type tracking, multi-line comment stripping, link-bracket stripping, and arrow/encoded nav variants close several false-negative classes. Documents the plain-text fallback for the broken `supervisor_add_addon_repository` redirect (my.home-assistant.io#698).
- **Phase 1 (foundation)**: spec doc with cheat-sheet-at-top, machine-readable rules.json, operator manual
- **Phase 1.5 (validator)**: Python generator at `validator/generate-hook.py` reads `commit-rules.json` and emits the Bash commit-msg hook (single source of truth — Bash hook is generated artifact, never hand-written)
- **Phase 1.5 (corpus)**: golden test corpus at `specs/test-corpus/` — 26 pass + 25 fail + 7 false-positives covering all 11 types, all 7 rule_ids, boundary cases (72/73 chars), exemptions, bot patterns, and known false-positive guards (`my-config`, `our-team`, version-in-body, period-mid-subject)
- **Phase 1.5 (templates)**: 7 drop-in files at `templates/` — per-repo CLAUDE snippet, CONTRIBUTING cheat sheet (self-sufficient for cloud agents), AUTHOR-NOTES.md (Tier 1A forks), .commitlintrc.json, per-repo workflow includer, dependabot snippet, README. All snippets use `<!-- BEGIN/END: commit-message-standards -->` markers for idempotent in-place refresh.
- **Phase 1.5 (CI)**: `.github/workflows/commit-lint-reusable.yml` — reusable workflow consumers call via `uses:`. Validates PR commit range bounded by `git merge-base origin/main HEAD`, posts per-commit review comments via `gh pr review`, emits markdown table to `$GITHUB_STEP_SUMMARY`, hard 60s timeout. Public repo so private/public consumers can both call it.
- **Phase 1.5 (CI)**: `.github/workflows/test-corpus.yml` — self-test workflow that validates the validator against the corpus on every push to engineering-standards.
- **Phase 1.5 (bootstrap)**: `bootstrap-repo.sh` — 12-step self-verifying installer. Vendors `commit-rules.json` SHA-pinned, drops .commitlintrc.json + workflow includer + dependabot config + CONTRIBUTING + CLAUDE snippet + AUTHOR-NOTES (if fork), generates local commit-msg hook, dry-runs against last 3 commits, checks Actions enabled, prints TTHW timer. Idempotent. Smoke-tested at 4s first run, 2s on re-run.


### Changed
- **`commit-rules.json` schema 1.0.0 → 1.1.0.** `subject.no_version_prefix` (a boolean the generator never read) replaced with a `subject.version_prefix` object. When `allowed: true`, `generate-hook.py` emits an optional 4-component ship-version prefix group (`vMAJOR.MINOR.PATCH.MICRO `) into the `SUBJECT_FORMAT` regex — so a PR title / squash subject like `v0.1.1.1 docs: …` validates. This supports gstack workspace-aware `/ship`, where the version is a landing-queue claim placed at the front of the PR title. Direct commits omit the prefix; the format stays `type(scope): subject` for them.
- **`VERSION_IN_SUBJECT` pattern narrowed** from `^v[0-9]` to `^v[0-9]+(\.[0-9]+){0,2}([ :]|$)`. Short version prefixes (`v2`, `v1.2.3`, `v2.10.11`) still block; the 4-component ship-version prefix no longer does. Rule_id unchanged — semantic narrowing, non-breaking (same precedent as the WEB_UI_DEFAULT widening below).
- **Corpus** gained `pass/ship-version-prefix.txt` and `fail/SUBJECT_FORMAT-version-prefix-bad-type.txt`, locking both directions of the new behavior. Full corpus now 60 cases, 0 mismatches.

### Fixed
- **Reusable commit-policy execution is now content-addressed and read-only.** The called workflow checks out validator code, rules, and commitlint configuration from its own exact `job.workflow_repository` / `job.workflow_sha`, verifies checkout origin and `HEAD`, pins third-party actions to full SHAs, installs commitlint from a committed lockfile with lifecycle scripts disabled, and never loads PR-head executable policy. PR review mutation is removed; sanitized rule IDs remain available in the job summary. A hosted exact-SHA fixture gates consumer repinning.
- **Dependabot config now covers package trees outside root** (issue #1). `bootstrap-repo.sh` step 4 vendored a fixed snippet in which every block said `directory: "/"`, so any manifest in a subdirectory was silently unmanaged: flora-signal's `server/package.json` (`@aws-sdk/*`, `ws`) for three months, mammamiradio's `ha-addon/` Dockerfile, ha-fp2-sleep's eight `videos/*` trees, and this repo's own `actions/ha-app-docs-lint/action.yml`, which sat on `actions/setup-python@ece7cb06` (v6) while Dependabot bumped the three workflow files to v7. Step 4 now generates the config from `git ls-files`: one block per ecosystem (npm, pip, docker, cargo, composer, gomod, bundler, github-actions), every directory listed explicitly. Explicit paths rather than globs because globbing in `directories` is documented but broken (dependabot-core#12348); one block per ecosystem rather than per directory because same-ecosystem blocks must not overlap; a `groups` entry once a block spans more than one directory because `open-pull-requests-limit` is not enforced across directories (dependabot-core#10395). Ecosystems with no manifest are no longer emitted at all, which also clears the phantom `pip`/`docker` blocks that produced "no dependency files found" noise. Fixture and vendored manifests (`fixtures/`, `_template/`, `node_modules/`, `.venv/`, …) are skipped and reported by path, never dropped silently. A directory already claimed by a hand-added block outside the markers is left to that block and flagged, since duplicate directories make Dependabot reject the whole file.
- **Managed `dependabot.yml` block no longer clobbers a hand-written config.** When the target file already declared `version:`/`updates:` outside the markers, bootstrap wrote a *second* `version:`/`updates:` document into the same file. YAML treats that as a duplicate top-level key and the later one wins, so the hand-written blocks parsed away to nothing — the exact blocks people added as the issue #1 workaround. The managed block is now emitted as bare list entries continuing the existing `updates:` list whenever the file already owns that key, and any layout the script can't place unambiguously (a top-level key after `updates:`, non-standard list indentation) is left untouched with a warning instead of being appended to.
- Marker refresh in `dependabot.yml` no longer inserts a blank line the create path doesn't emit, so the first re-run is byte-identical instead of showing a one-line diff.
- `exemptions.trusted_bot_skips` is now actually read by CI. The reusable workflow hardcoded a lone `WHY_REQUIRED` check, so editing that array in `commit-rules.json` changed nothing and the field was effectively decorative. CI now resolves both `trusted_bots` and `trusted_bot_skips` from the consumer's vendored rules, and passes a message only when the author is a trusted bot *and* every rule it tripped is in the skip list — one non-skippable violation still fails, so this is not a general bypass.
- Bot allowlist now applies to the PR title, not only to the commits in range. The title check ran with no author awareness at all, so every grouped Dependabot PR failed on subject length regardless of author. `SUBJECT_TOO_LONG` added to `trusted_bot_skips`: Dependabot's grouped titles ("…in the core group across 1 directory") pass 72 characters by construction and no Dependabot setting shortens them. Schema version 1.1.0 → 1.2.0.
- WEB_UI_DEFAULT regex widened from `^Update [A-Z][a-z]+\.md$` to `^Update [A-Z][A-Za-z]*\.md$` so it correctly catches all-caps filenames (`README.md`, `CHANGELOG.md`, `LICENSE.md`). The original regex required mixed-case (`Readme.md`), missing the most common GitHub web-UI default. Caught by CI on first push of test corpus. Rule_id unchanged (semantic widening, not a breaking change).
- Corpus `# expected:` headers updated from `FORMAT` → `SUBJECT_FORMAT` to match the actual rule_id the validator emits. Naming-mismatch caught by CI on first push.

### Conventions
- Conventional Commits format with body-when-it-matters policy (Why required only for `feat` AND >50 lines)
- Metadata trailer policy (`Skill-Run`, `Test-Suite`, `Reviewed-By`, `Tool`) with fork-strip behavior on upstream-bound branches
- Override trailer (`Policy-Override`) for sanctioned bypass with audit log to `~/.commit-bypass.log`
- Bot allowlist (`renovate[bot]`, `dependabot[bot]`, `pre-commit-ci[bot]`, `app/github-actions`)
- Subject exemptions (`Merge `, `Revert `, `cherry-pick: `, `[hotfix] `)
